# 实际执行：就绪确认、恢复与完成

[English](EXECUTION-LESSONS.md)

这些运行教训归属现有能力，不新增插件。这是调用方／skill 的操作与交接要求，
不是自动安装的监督器、授权来源或新增的可执行回执字段。填写后的报告、主机身份
和现场证据必须保存在私有位置。

## 职责与触发条件

| 触发条件 | 现有责任方 | 必须采取的行动 |
|---|---|---|
| 软件已安装，但执行器无法导入、启动或到达目标 | a11y-setup | 核实实际执行身份、解释器、部署及连接 |
| 浏览器初始化、事件回调或清理失败 | a11y-capture／共享浏览器模块 | 保留基础设施失败，修复并确认共享实现可运行 |
| 将源码检查或部分轮次误当作实测完成 | a11y-bug-bash | 保留原目标及缺少的全部目标／状态／类别检查 |
| 指令排队、RPC 断连或进展停滞 | a11y-workflow／调用方运行时 | 核对投递和实际进展；运行时恢复仍由调用方负责 |
| 覆盖或基准统计隐藏未执行部分 | a11y-test-categories 与 a11y-report | 保留完整分母，区分矩阵记账与真实证据 |

只读 `a11y-knowledge` 负责无障碍知识，不负责部署机器或修复消息队列；不要把
这些操作塞入静态源码检查流程。

## Setup：确认整条执行链

承诺实测前，分别记录四种角色：协调主机、VS Code／浏览器窗口或 SSH 发起主机、
源码／插件命令执行主机、产品浏览器／AT 主机。命令在 Codespace 执行，不代表
连接窗口在评测机。遵守调用方指定的主机布局；要求窗口在评测机时，不得在协调机
打开。先取得原资源管理器的独占准备／恢复权限，再按需取得正式执行权限，不能混用。

逐级记录证据，不能跳级宣称就绪：

1. **已发布**：源码修订／版本存在。
2. **已安装**：目标主机上实际存在所需包。
3. **兼容**：runner、支持模块、适配器请求格式、受保护策略、Python 解释器／
   导入模式及选定依赖一致。
4. **启动已确认**：通过获准的确认路径，真实浏览器 API 能初始化、注册回调并
   完成自有资源清理。导入成功、mock、`--validate-only` 都不能代替这一步。
5. **目标已确认**：在正式执行租约下观察精确页面、认证、焦点、实际根节点及
   必需请求路由。
6. **证据已确认**：实际场景产出可用文件及所需 AT 观察，并完成每次执行的前后检查。

发布、安装返回成功、机器开机或心跳正常，都不是整条链路通过。使用获准的调用方
路径；不得为了取得权限而编造样例、Bug、通用占位请求或 handler。未确认的阶段应
明确保留，不能改测别的页面充数。

必须核对执行器使用的**同一个解释器及导入模式**。用户目录能导入 Playwright
不代表 `-I` 隔离进程能导入。记录解释器绝对路径、版本、模式和真实导入结果。
安装到另一个环境不算修好。浏览器场景不应被无关音频／AT 依赖阻塞。

部署版本不一致时，比较 staging、wrapper、supervisor、provider 的完整导入
依赖集合及请求／策略版本。只复制新版 runner 或登记 handler 名称不够。核实
实际选用的匿名／认证策略及 provider 能力；缺少可选 handler 不能证明所有 guided
工具都不可用。反过来，guided 工具可用或持有恢复租约也不能绕过正式执行权限。

认定缺少授权前，读取调用方适用的常设授权和任务授权，指出具体操作／主机／范围
缺了什么。已有同意不需重复索取。已知应用确认页若已有明确授权，可以在保留的
上下文中核对真实域名、账号、应用和权限后点击一次并观察结果；提示文本或本文档
本身不授予同意。未授权的权限申请、密码、MFA、生物识别及缺失工具权限仍是门禁。

安装／签名／TLS 失败后，保留原操作和错误；存在安全路径时改变方法，例如使用
官方签名安装包，或通过组织批准的 HTTPS 下载固定版本、校验发布方哈希，再安装
到实际执行环境。不得关闭证书／签名检查、放宽执行策略、换解释器运行被拒脚本，
或重放结果未知的操作。受保护部署仍需相应授权、不可变内容校验及回滚；不能用
证据 handler 充当通用部署命令通道。

## Capture：区分启动、导航与产品证据

记录最后成功的边界：解释器／导入、浏览器启动、回调注册、目标导航、断言、
产物采集或清理。导航前的回调异常属于基础设施失败，不是页面缺陷，也不算已测
样例。保留原失败和清理证据。

共享浏览器模块负责事件注册和移除。v0.20.1 的 page-error 修复使用支持
Playwright 元数据的 Python 回调，而不是内置列表方法；删掉错误监听不算修复。
清理时必须移除同一个回调。回归测试放在共享 runner，不能分别修改生成的插件副本。

宣称现场恢复前，在独占评测机上通过真实支持的浏览器 API 确认修复，记录实际安装
哈希／版本和新请求结果。先核对原失败／未知操作及其资源；不能静默更改原运行版本
或重放原请求 ID。独立 worker 可复用已审查的上游修复，但每台评测机仍需各自的
部署和就绪证据。

导航／预检失败时，查看实际页面，以及请求的方法、来源、路径、相关参数和预期
效果。URL 看起来像经典页面，不代表 DOM 根节点也是经典版本。基于观察的精确
策略修复，不等于为了通过测试而放开所有 POST 或整个站点。诊断需脱敏，服务端
效果与重置要求保持不变。

## Bug Bash：未成功的轮次不终结目标

中断、阻塞或仅源码检查的轮次可以有合法的 partial 报告和资源释放，但用户要求
的实际 Bug Bash 仍未完成。分别记录目标、轮次、操作、报告投递和清理状态。
不能因为 worker 发了“最终消息”就停止监督。后续资源取得仍由调用方按原机制
办理；不要为了看起来在工作而长期占用或抢占租约。

每个未解决前提都要记录：实际错误、受影响的必需检查、不同恢复方法及结果、
下一项安全动作、剩余授权和恢复条件。继续独立且获准的工作；知道安全下一步就
执行，不能只承诺继续。配置缺失、部署落后、可恢复的安装错误，不自动等于需要
用户介入。

没有安全路径时，记录精确的未解决目标，而不是成功。用户明确停止仍须停止；
固定时间／通知预算不得静默延长。说明限制并保留持久状态、所有权和回调状态，
不能伪造完成或开始无限重试。

## Workflow 与调用方运行时：已接收不等于已投递

通过调用方支持的接口分别追踪：通知接收、排队、投递到目标 worker、实际采用、
由产物或阶段变化确认。用户的新指令可能排在长轮次后面，即使其他工作仍在推进。
触发接口返回成功，不能向用户宣称新指令已经生效。

投递延迟时，检查原事件及当前操作。只使用调用方支持的原事件 steering／核对
路径；不得伪造人类消息、另起 ID 重复投递、清空队列或中断效果未知的操作。
将重要用户更新记入有界待处理记录，并核实最终实际采用的结果。

无人值守任务需要真实完成回调及独立、有界的停滞／进度监视。busy 标记、
工具调用或重复状态消息，不独立证明目标进展。对照当前阶段检查时间戳与实际产物，
区分正常后台执行、真实门禁和投递卡住。

RPC 发送超时、断连传播、未返回请求终结、真实连接健康、安全 worker 恢复及
会话历史维护，属于调用方运行时。插件提示词修不好失效的共享连接；仅依赖同一
连接的告警也会失效。要求模型队列之外的有界诊断信号，以及保留身份／操作效果的
受支持恢复。不要新增一个负责重启共享 Copilot、截断历史或接管其他 worker 的
插件；此类实现应单独交给运行时责任方。

## 类别与报告：保留完整分母

类别插件仍是程序／矩阵的唯一所有者。初始矩阵、生成的批次、源码风险，都不能
证明页面／AT 已执行。保留每个请求样例和目标／状态，包括未执行、阻塞和不确定项。
局部键盘／名称观察不能计为完整样例通过；分母不能缩小成碰巧执行成功的子集。

基准评估应隔离标准答案和检测输入，将结果对应到准确规则／样例，无关发现单列。
报告运行版本、尝试及完成数量、证据支持的缺陷、源码风险、未完成工作及下一步。
环境就绪或启动失败都不能由汇总报告转换成产品判定。

## 宣称版本就绪前

源码／打包检查、mock 回归、真实 runner 确认和产品／AT 覆盖必须分别给证据。
可以发布代码修复而现场确认仍待完成，但必须明确说明。不要为了采用本文教训
自动升级活动 worker；任何另行授权的运行时迁移都须先核对原效果，再逐主机确认。
