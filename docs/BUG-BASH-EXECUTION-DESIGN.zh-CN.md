## 1. 产品目标

给定 feature context 和验证说明，`/a11y-bug-bash` 应生成有界、可复现的无障碍问题发现报告，包含：

- 实际页面问题，以及步骤、影响、观测行为和证据。
- 只读源码风险，以及源码修订、推理依据和运行时确认步骤。
- 每一条计划覆盖行，包括阻塞、未执行和不确定的检查。
- 精确环境/工具来源、自有资源清理和实际交付的报告。

它必须适用于含多条用户路径、多种状态的大 feature，而不只是单个控件或一次扫描。完成一轮不等于 WCAG 认证。问题发现不授权产品修改/构建、自动创建工单、改变指派、创建 PR、公开上传或安装环境。这些操作需要各自的授权和工作流。

保留 `plan-only`、`page-only`、`source-only` 和默认 `both` 模式。仅源码和仅计划模式不需要 Windows、浏览器准备或实时 provider。真实页面/辅助技术（AT）工作面向经过验收的 Windows evaluator 部署。某条路径不可用，不应阻止独立且已授权的工作，但必须保留为覆盖缺口。

## 2. 设计原则与兼容性

通过稳定能力契约组合可验证场景。模型提出场景与路由；可信运行时强制执行授权、证据、资源归属和完成条件。路由与跨步骤 A11y 知识留在主上下文，场景细节按需加载，确定性探测使用工具。只有较大推理过程的输入输出确实适合隔离时，才使用独立上下文。先使用已验收静态 profile，再单独评价自适应选择和离线变更；不能削弱必需覆盖或接受门禁。

保留现有打包格式，本设计不包含 manifest 迁移。使用实际协商的 SDK/协议和观测到的工具支持，不假定宿主支持新协议版本或可选 Tasks 扩展。校验 schema，重连后核对持久状态；仅靠通知不够。MCP 任务句柄不证明桌面归属、证据正确、清理完成或交付。权限由宿主/provider 边界强制执行；skill 的 `allowed-tools` 元数据不是安全边界。包必须自包含，但仅完成安装不会调度工作，也不证明实际宿主已就绪。

## 4. 这里的 everything is a plugin 是什么

| 概念 | 职责 |
|---|---|
| Plugin | 可独立安装、版本化的分发单元 |
| Skill | 包内按需加载的过程及相关参考资料/脚本 |
| Tool/provider | 类型明确的可执行操作；provider 负责真实宿主作用与证据 |
| MCP | 可选的宿主到工具连接，不是插件之间自动调用 |
| Agent | 可选择场景或分析问题的推理上下文；每个插件不必配一个 |
| Workflow | 调用方负责的组合，具有依赖、预算和接受门禁 |
| Trusted runtime | 强制执行身份、授权、持久修改、资源归属和外部作用核对 |

依据稳定能力边界、独立用例、权限、执行宿主或发布周期拆分。不要为每次点击、按键、断言或文件创建插件。逻辑子能力不一定是嵌套安装包、独立 MCP 进程或远程子代理。

### 推荐能力图

| 逻辑子能力 | 包决策 | 输入 -> 输出 | 边界 |
|---|---|---|---|
| Feature 规划 | Bug Bash 内部 skill/模块 | Context + 验证说明 + 知识 -> 版本化覆盖计划 | 无外部作用；不能静默改变 feature 或请求范围 |
| 知识 | 复用 `a11y-knowledge` | 技术栈/版本 + 问题或限定源码 -> 有引用的指导/风险 | 只读；先通用规则，仅在适用时加载项目规则 |
| Setup | 复用 `a11y-setup` | 所需能力 + 实际宿主 -> 限定范围的清单/准备计划 | 默认只检查；准备操作须单独授权 |
| 资源连接 | 复用 `a11y-resources` 和原部署权威 | 宿主要求 + 任务身份 -> 归属/状态证据 | 现有公开 status 不等于 acquire；使用前必须实现新的类型化任务获取集成 |
| 浏览器检查 | 拟议 `a11y-browser` 能力，先作为共享内部模块 | 自有浏览器 + 封存场景 -> 观测与产物 | 键盘/焦点、渲染语义、批准的扫描器和视觉适配器；不声称真实 AT 结果 |
| AT 检查 | 为 `a11y-capture` 扩展明确的 discovery 操作和 AT 适配器 | 自有桌面 + 封存场景 + 所需 AT -> 观测到的语音/识别/媒体 | NVDA/Narrator/Voice Access 适配器是逻辑子模块，不是三个必装包 |
| 源码审查 | 将 knowledge 的只读审查复用为子步骤 | 限定源码/修订 + context -> 源码支持的风险 | 初期不另建 `a11y-source-review` 包；knowledge 审查内不编辑源码、不运行测试或 shell |
| 证据完整性与行为 | 扩展 `a11y-validate`，复用产物哈希 | Discovery 证据清单 -> 独立的完整性和行为决定 | 需要新的 discovery schema；现有 evidence-v1 检查器不能接受任意 Bug Bash 报告 |
| 报告 | 初期为 Bug Bash 内部纯模块 | 覆盖 + 已接受观测 + 源码风险 + 缺口 -> 私有报告 | 不依赖 `a11y-publish`；生成报告不是发布工单/PR |
| 恢复、清理、交付 | 通过限定范围的 provider 复用 `agent-operations` | 原操作/归属 + 进度 -> 核对、清理和交付回执 | 窄范围恢复不能替代完整清理；不能广泛终止进程 |

因此，首个实现最多新增一个包（`a11y-browser`），且要等其独立契约确实有用。不要仅为匹配架构图就新建 `a11y-at`、`a11y-evidence`、`a11y-report`。只有其他调用方需要稳定独立接口，或模块确有独立发布/权限周期时，才重新考虑抽包。

有已授权工作项提供 context 时，可选用 `a11y-intake`。`a11y-publish`、`a11y-workflow` 和 AgentOW 都不是 Bug Bash 的依赖。已接受的问题之后可以进入单独授权的修复流程，但仍须遵守该流程真实 BEFORE/AFTER、资源、源码和发布门禁。

### 推理是另一项独立的组合选择

主推理上下文负责 feature 目标、覆盖缺口与路由。按需渐进加载标准/项目知识，不一次加载全部 skill。大型源码风险分析或证据解释可以使用隔离上下文，前提是提供完整限定输入、预期输出、终止规则和可展开证据指针。小查询和确定性 DOM/焦点/哈希操作保持直接工具调用。逻辑能力存在不意味着需要隔离子任务，也不能假定实际子代理可用。

上下文隔离不授予额外权限，也不隔离桌面。独立行为评价需要自己的证据和评判标准；新模型重复产出者的结论还不够。

## 5. 打包与实际调用

一次 Bug Bash 安装仍应足以提供说明与共享模块。保留 `bundleKnowledgeReview` 和 `bundleSetup` 作为单一源码组合模式。手写变更归属 `src/`；不得手改生成的 `plugins/`。不再发布根目录兼容导出。

目标可执行包可以内置共享运行时，并提供命名空间明确的 Bug Bash MCP 入口。这是需要显式选择加入的新增能力，不是 0.15 已有能力。保留无需 provider 的计划/源码用法，不将 Windows setup 或执行配置变成其前提。

宿主调用已知能力 dispatcher，再由 dispatcher 调用共享实现或操作者配置的可信 provider。它不会让一个 MCP server 自动发现并调用兄弟 server。直接宿主工具只有经过明确支持的适配器才可使用；工具出现在会话中，不会自动注册为可执行 provider。

拟议的包内 `capability-lock.json` 记录每个内置模块的精确实现版本、摘要、契约版本和源码来源。这是我们自己的构建产物，不是标准 `plugin.json` 依赖字段。每轮每项操作选择一个 provider；不得并行执行内置和独立副本，也不能在超时后静默换版本。

运行固定这些绑定。以后包更新服务于新运行；正在进行的运行保持固定，或采用单独验证的迁移。插件文件变化后按需重装、重启宿主，并在实际执行机器上确认加载的 skill、工具和 handler 版本。

### 服务解析与已验收 profile

把每项能力视为稳定服务/操作契约，具有明确的定义、一个选定提供方及可能的多个消费者。兼容扩展现有能力注册表和可信连接；不引入第二个加载器、任意可执行程序解析，也不强制更换框架。声明式前提决定激活。在外部作用发生前拒绝不兼容契约、提供方歧义、循环或缺失硬依赖。服务名和检索到的 skill 不授予执行权。

拟议 browser-only profile 只要求自己的浏览器依赖。拟议具名 AT profile 加入所需 AT 和证据链，而不是所有录制器/驱动。Profile 表示经过验收的组合，不是新包名，也不声称这些组合今天已经可用。记录实际 profile、provider/skill 版本、选择策略/图修订和模型配置。未知成本或后端模型版本须明确标注。

选择时提供元数据；选中后才加载详细说明；大型产物按引用取回。分别记录推理上下文峰值和累计 token，并在可测时记录延迟/缓存影响。不能静默热替换 provider，或释放活动操作的监督器。释放插件注册项不能取消原生工作、撤销外部作用或释放资源归属。

## 6. 大 feature 的组合方式

例子：一个 item picker，包含搜索、分页/虚拟化结果、选择、确认、取消、空/错误状态和重新打开行为。

```text
Context + 验证步骤
          |
          v
计划 + 知识 -> 所需能力集合 + 覆盖修订
          |
          +----------------------+
          |                      |
          v                      v
限定范围的 setup/check       只读源码审查
          |                      |
类型化、归属明确的执行            +--> 建议运行时场景
          |                           （新计划修订，不扩大范围）
          v
浏览器检查 -> 定向真实 AT 检查
          |               |
          +-------+-------+
                  v
观测/证据校验 -> 有界候选问题确认
                  |
                  v
汇总报告 -> 自有资源清理/释放 -> 最终报告 + 交付
```

只有工具独立、已授权且不修改共享桌面时，源码审查才可以并行；小型审查不需要另开 Agent。同一 evaluator 上的页面操作、焦点变更、AT、录制和复位必须串行。不同独立场景可以使用不同的独占 evaluator，但每个场景的重复/对比仍固定在已分配宿主与环境上。不能仅因能力不同就并行。

| 阶段 | 进入门禁 | 操作与输出 | 退出门禁 |
|---|---|---|---|
| Scope | Feature 与授权已明确 | 记录模式、允许路由/数据、预期行为、预算和未知项 | 不虚构 feature，不隐含危险操作 |
| Plan | 范围可用 | 用户路径 x 可达状态 x 适用维度；稳定行 ID、优先级、预期证据、复位 | 映射全部输入验证步骤；说明排除理由 |
| Prepare | 所需能力集合已知 | 限定清单；必要时执行单独授权的 setup/恢复 | 实际宿主的所需连接可调用；隔离可选缺口 |
| Acquire | 完整类型化请求已校验且 worker 可见 | 原部署权威原子地派发/获取 | 健康且独占的 evaluator；恢复归属不等于执行归属 |
| Execute | 固定计划/provider，具备原始授权 | 逐行复位、操作、观测、采集；独立执行源码审查 | 每条尝试行有观测或明确失败；不作无支持的 AT 断言 |
| Confirm | 候选由真实观测支持 | 从已知前提进行有界安全重复；独立行为评估 | 如实说明可重复性，保留不确定性 |
| Aggregate | 已知操作已核对或明确尚未解决 | 分开问题、风险、疑问和缺口；只连接已证实的重复项 | 所有行 ID 均核算；无构建绑定则不从源码推定页面根因 |
| Cleanup/deliver | 已枚举原始自有外部作用 | 保留证据、恢复修改设置、停止自有资源、经原权威释放并交付报告 | 适用清理和交付均已确认；不能把未核清外部作用隐藏为完成 |

准备不是提前预留执行资源。任何 setup/恢复交互都需要原权威对应的独占 setup/恢复归属；否则准备只能是只读规划/状态查询。产品交互和证据必须在获取执行权之后开始。不能把恢复探测重新标成产品覆盖结果。

普通探索步骤不可能预先全部知道。规划器可在授权范围和预算内追加新行，形成新计划修订。绝不能删除旧行、重写已接受回执或静默延长预算。已提交操作保留原计划/场景哈希；新修订不能改变它原本获准执行的内容。

覆盖维度仍以 `src/bug-bash/coverage.json` 为准。知识提供适用标准和组件预期，不依赖规划器猜测。先覆盖主路径和高影响阻塞，再覆盖相关视觉/AT 变体。有界轮次必须明确时间/行数/确认次数限制，并预留清理时间；不能保证穷尽所有无障碍情况。

### 受约束的自适应组合

组合单元是可验证场景，不是 Agent 或插件：前置条件 -> 操作 -> 预期结果 -> 能力 -> 证据 -> 复位。生成适用的路径/状态/维度组合，而不是盲目笛卡尔积。换 provider 也必须满足同一已接受场景。

规划器先映射输入验证说明与必需覆盖，再从能力目录和相关经验提出有界候选。绑定计划前，确定性接受逻辑检查 schema、依赖、授权、资源兼容性、所需证据和预算。

分清两类关系：

- **硬关系：**声明的服务前提、授权范围、必需行、桌面独占、证据门禁和预算。
- **软关系：**检索相关性、观测到的共用/顺序/成本，以及改进 skill 发现的描述。它们影响提议，不授权外部作用。

学习不能因为某个必需屏幕阅读器行成本高或很少成功就删掉它。缺少 AT 只阻塞该行，独立浏览器/源码工作可继续。自适应选择失败时，仅可回退到满足同一范围与契约的已验收静态 profile，并记录此选择。

对于 picker，发现异步搜索结果后，可增加焦点保持和状态播报场景，需要时采集具名真实 AT 输出。只在范围和剩余预算内以新计划修订接受追加项。不能改写运行中的操作，也不能把旧证据用于新场景。每条适用但阻塞/未运行的行仍留在报告里。

## 7. 版本化契约

以下记录和语义操作是**拟议内部契约**，不是可调用工具或现有 MCP/manifest 字段。先实现 schema 和校验器，再暴露能力。复用现有操作身份、哈希、私有 provider 和核对辅助逻辑；未经兼容的版本化扩展，不向当前严格 context schema 注入新字段。

| 记录 | 必需内容 |
|---|---|
| FeatureContext | Feature ID、用户目标、授权引用、请求路径、允许环境/路由/数据、验证说明、源码绑定或明确未知、预算 |
| CoveragePlan | 计划修订/哈希；稳定行/场景 ID；前提、操作/复位、预期行为、知识引用、优先级、所需能力与证据类型；声明的约束、选择理由和绑定的 profile/provider/skill/检索/模型配置 |
| CapabilityDescriptor | 稳定服务/操作 ID 与 schema 版本、支持宿主、输入输出 schema、声明前提、作用类别、权限、互斥要求、prepare/execute/reconcile/cancel/cleanup 支持及边界、期限策略；推理模式、渐进披露/上下文预算、成本/缓存估算与实测 |
| CapabilityObservation | 实际宿主/工具/运行时版本和哈希、观测时间、范围、授权/归属引用、重启/配置缺口；不含秘密 token |
| StepRequest | 父 task/run、step/operation ID、不可变 request ID、owner/authority、计划/场景哈希、provider 绑定、限制和精确输入 |
| Observation | 行 ID、尝试步骤、实际结果、预期比较、证据引用、使用的具名 AT、不确定性及源码/部署绑定 |
| StepResult | 回显身份、执行状态、原因、已接受观测、证据清单、清理范围，以及适用时的待定进度/恢复/回调字段 |
| Report | 请求/执行/排除范围、全部行、分开的发现类别、证据索引、未核清外部作用、清理、下一步和交付回执 |

身份层级：`taskId` 对应授权/工作项；`runId` 是一次有界轮次；`stepId` 是一个逻辑子步骤；`operationId` 映射现有独立操作日志；`requestId` 标识原生外部作用。Token 保留在可信连接中。仅凭注册表条目或模型提供的 owner 字符串，不能证明授权。

不要混淆三类状态：

- 执行：queued、submitted-unknown、running、finished、cancel-requested。
- 覆盖：现有 `planned`、`observed-no-issue`、`finding`、`blocked`、`not-run`、`not-applicable`、`inconclusive`。
- 任务交付：pending，或已确认报告交付及适用清理。

成功执行检查可能发现产品缺陷；适配器报错不是产品缺陷；一个操作结束不等于整个 feature 轮次完成。通过显式适配器转换现有 provider 的 `receipt.outcome`，不能把旧 `pass` 重新解释成“feature 没有无障碍问题”。

## 8. 证据与报告正确性

持久运行时接受采集产物时，要求 SHA-256 和受根目录约束的文件引用。保留时间戳、工具/AT 版本、执行宿主身份、场景、路由、样例、flags、权限、viewport/zoom 和实际构建绑定。构建身份未知就明确写未知，不能虚构 HEAD。

完整性校验检查 schema、字节、绑定和行核算。独立行为评估检查证据是否支持主张。两者不能相互替代。哈希只证明取样字节与声明一致，不证明截图真实、语音确实发生或人能够使用 UI。产出模型不能自己编写可信回执来绕过门禁。

真实屏幕阅读器结论需要具名真实 AT 的观测输出；ARIA 树不是语音。语音控制结论需要真实识别和目标归属。扫描器输出是待结合实际渲染上下文确认的候选。视觉结论需要相应渲染测量/上下文。纯源码风险没有运行时观测就不能变成页面问题。

以 picker 为例，“取消后焦点未恢复”需要操作序列及操作前后观测的焦点目标。某个文件缺少 `focus()` 调用，在理解父级/库行为前只是源码风险。不能仅因 Escape 没关闭对话框就断言键盘陷阱。

报告规则：

- 保留全部计划行，包括历史修订和已被替代的行。
- 覆盖分母为当前适用行，之前修订单列。只排除有理由的 `not-applicable`，不能排除 blocked/not-run。
- 分开已尝试覆盖与有结论覆盖；无结论尝试不能抬高有结论总数。
- `complete` 要求每条当前适用且请求的行都有确定的 finding/no-issue 观测，并确认清理和报告交付。
- `partial` 保留 blocked/not-run/inconclusive；`blocked` 表示关键的必需执行无法推进；`plan-only` 不属于已执行覆盖。
- 取消/放弃是带原因的生命周期结果，不是符合标准的另一种写法，也不能抹去未知外部作用。

清理尚未解决时可以交付 partial 或 blocked 报告，但这不关闭执行义务、不释放归属。关闭生命周期需要清理证明，或明确授权的交接，记录剩余责任方、资源及恢复条件。

## 9. 可靠性必须可执行

### 持久状态与监督

扩展共享操作存储，增加 feature 级日志，引用子 operation ID、已接受回执摘要和单调递增状态修订。在聊天上下文之外保留只追加迁移日志和可重建的当前快照。调用 provider 前原子记录步骤意图。采用现有已验收存储/锁模型串行化修改；不能自动过期废弃锁，也不能新建竞争性归属存储。

无人值守执行的准入需要已确认的执行器、持久进度位置、完成回调和独立可用的停滞 watcher。Twin 仍要求回调。现有显式 CLI caller-poll 支持，只在已部署有界调度器及原期限下有效。安装包或拿到 pending 回执，都不会自动安装监督能力。

监督器按任务 ID 核对执行器、待定原生操作、回调、watcher 和终态回执。重启或压缩历史后，从日志重建工作，而不是依赖对话摘要。回复或心跳不是进展；行状态推进、产物持久化或回执核对才是。

推理不进入确定性重放：保存已接受计划和观测，不重新运行模型来重建旧决策。重启后的 dispatcher 消费这些记录并核对外部作用。它不能仅因自身日志持久就承诺外部执行恰好一次；这依赖 provider 的幂等/核对契约。

### 失败与改变假设的恢复

| 失败 | 必须采取的反应 |
|---|---|
| 提交后 RPC 超时 | 保留同一 operation/request ID，核对原始外部作用，不以新身份执行 |
| 回调丢失或通知重复 | 幂等核对持久状态；watcher 发现无进展，不凭空再开一个 worker |
| 聊天/worker 重启 | 恢复固定输入/归属，检查待定作用，继续下一安全动作；不重放已完成修改 |
| 交互 60 秒或首个有界等待内无变化 | 检查认证/焦点/页面/资源状态，再次等待前改变恢复假设 |
| 后台工作 5 分钟无持久进展 | 读取限定诊断并核对执行器；不能依赖进程仍活着 |
| 可选 AT/音频/扫描器缺失 | 只阻塞依赖行，继续独立浏览器/源码行 |
| 运行时/schema/哈希不匹配 | 采集前失败；走批准的部署路径，不扩大权限，不当作产品 bug |
| 浏览器复位或 AT 状态不明确 | 保留产物和原归属；建立精确状态后才安全重试 |
| 密码/MFA/同意或授权不可用 | 停止受影响操作，保存明确恢复条件；只继续独立已授权范围 |
| 清理或报告交付失败 | 保留义务和限定续跑；不能报告任务完成 |

只重试已核对外部作用、已知安全的操作。将可恢复阻塞判为终态前，采用有界、证据驱动的恢复，包括首次尝试后改变假设，除非继续操作不安全或违反外部限制。预算限制重试，但不会释放未知外部作用。到达期限终止的是等待，不一定是原生执行。

### 任务范围内的取消

运行时需要限定到精确授权/任务身份和状态修订的取消操作。修改前必须枚举自有子任务、活动外部作用、回调/watcher，以及依赖共享服务的其他任务。

停止 watcher 不等于取消任务。对于仍获授权的未完成工作，在移除唯一续跑路径前，要证明有已授权替代路径。明确要求停止任务时，绝不能新建 watcher 绕过。停止维护不能隐式停止由另一份授权支持的 feature 执行。共享聊天、包名或机器不代表共享任务范围。

在精确执行器确认安全停止、清理已核对前，使用 `cancel-requested`。只关闭自有进程身份/浏览器上下文，不关闭所有同名进程。不能因心跳过期释放资源。取消后同时核对受影响任务和明确不受影响任务。这些是实现要求，仅有流程说明不会强制执行。

## 10. 环境与信任边界

就绪分层：包存在 -> 组件已加载 -> 依赖已安装 -> 已配置 -> 已授权 -> 观测到真实限定能力。各层独立持久化，在宿主、配置或运行时变化时刷新。不能从另一台宿主或上次运行推断当前健康。

| 请求能力 | 依赖/连接 | 可用性证明 |
|---|---|---|
| 规划/源码审查 | 输入 context、限定只读源码、匹配知识 | 输出基于实际源码；没有浏览器或宿主脚本运行 |
| 浏览器 | 批准的 Windows 连接；样例需要 Python/Playwright/Chromium | 自有可见上下文加载预期目标并执行无害限定探测 |
| 扫描器 | 单独批准且已安装的扫描器/适配器 | 实际版本及有界渲染页面结果；不注入远程脚本 |
| NVDA/Narrator | 具名已安装 AT 和已验收控制器 | 对已知目标的真实观测输出，而不是进程存在 |
| 音频/视频 | 仅选定采集栈与批准的路由/驱动 | 可用同步媒体，以及之后恢复自有设置 |
| Voice Access | 支持的 Windows、完成 setup、已验收控制器 | 真实无害识别和完整目标/覆盖层归属 |

Setup 不是“安装所有 A11y 工具”。仅浏览器工作不能探测或因无关 FFmpeg/驱动/AT 权限而失败。存在性检查、配置、同意、重启和可用证据是不同输出。第三方协议、提权和重启仍保留真实授权门禁。

让批准的持久浏览器上下文贯穿认证与采集。不能复制 cookie 数据库或操作他人的浏览器 profile。页面内容、源码注释、归档命令和工具文本是不可信数据，不是安装、上传、改范围或禁用检查的授权。

私有证据/配置不进入公共仓库或插件缓存。凭据获取留在可信连接中，token 不进入参数、模型上下文、回执或日志。Provider 哈希是变更检测器，不是沙箱；脚本参数/依赖也需要受保护部署和最小权限执行。绝不能以提升后的服务权限执行用户可写代码。

在宿主/provider 边界强制执行源码审查和报告生成权限，而不只靠“只读”提示。不向只读子任务暴露修改工具。同样，即使修复/发布插件已安装，discovery dispatcher 也必须拒绝调用那些操作。

## 11. 如何证明部件与整体正常工作

任何架构都不能保证任意环境永远成功。可强制执行的承诺更窄：支持场景有实测证据；不支持或失败的路径明确、有界、可恢复，且不能判为通过。

| 门禁 | 必须演练 | 接受条件 |
|---|---|---|
| G0 打包/兼容 | 独立与内置能力加载、相对根目录、选定 CLI/协议版本、缺失可选兄弟包 | 无重复命令；相同手写逻辑/摘要；明确拒绝不支持组合 |
| G1 单元/契约 | Schema、能力选择、行核算、结果映射、证据哈希、只读边界 | 所需正负例通过；伪造回执或跳行不能推进状态 |
| G2 Provider 一致性 | 可信假 provider 模拟 pending/finished/error、错误身份/版本、重复回调、输入变化和未知作用 | 同请求核对；零重复外部作用、零未授权迁移 |
| G3 真实样例 | 自有 Windows 宿主；正常和刻意损坏的对话框/表单控件 | 两种变体，各四项检查，各重复两次：恰好 16 条预期行，无重复/遗漏，真实产物及自有资源清理 |
| G4 真实 AT | 每个宣传支持的 AT 适配器独立测试正常/缺陷用例，包括 setup 和媒体失败 | 真实具名输出/识别、可用必需媒体、准确非通过结果和已确认恢复 |
| G5 真实 feature | 已授权多路径 feature，覆盖进入/退出、空/错误、重复使用和相关视觉/AT 状态 | 每条约定行均核算；问题可复现或明确间歇性；源码风险独立 |
| G6 可靠性 | 步骤中重启、回复丢失、作用后超时、watcher 丢失、取消无关任务、evaluator 忙、旧运行时、清理失败 | 无抢租约、重放作用、孤立的已授权任务或假完成；恢复可追溯到持久状态 |
| G7 发布 | 在干净支持宿主安装发布版本，确认加载哈希，重跑代表性契约/现场用例 | 可复现支持 profile、如实限制、已验收 provider、经过演练的回滚路径 |

G3 行键严格为：
`<healthy|broken>-<dialog-entry|dialog-escape|email-name|form-error>-<1|2>`。
正常控件应有预期 no-issue 观测，缺陷控件应有预期发现。工具验收通过会刻意包含检测到的缺陷，它不是产品/AT 符合标准通过。PNG/ARIA/焦点产物需要真实字节与哈希，不能伪造文件补齐缺行。

源码风险路径可以对同一样例修订单独运行。记录风险依据和确认方式；不能把它计为额外页面执行，也不能假装它证明语音发生。

G6 要明确启动独立测试任务 A（维护）和 B（Bug Bash）。停止 A，证明 B 仍产出持久下一步产物。没有替代路径就移除 B 唯一 watcher，必须被拒绝。明确取消 B 后，要求不产生替代工作，只进行已授权核对/清理。控制器重启、重复交付后重复演练。这样取消隔离才是可观测运行时属性，而不是提示中的承诺。

优先使用现有套件：`tests/bug-bash.test.mjs`、`setup.test.mjs`、`operations.test.mjs`、`waiting.test.mjs`、`core.test.mjs`、`evidence-files.test.mjs`、`packaging.test.mjs` 和适配器测试。PR #22 增加样例请求/宿主门禁覆盖；CI 不冒充真实 Windows/AT。实现每个新契约时，在负责该功能的套件增加定向用例。

逐运行/profile 记录质量信号：必需行、有结论/已尝试覆盖、已确认和无结论候选、抽样误报、重复作用数、归属违规、恢复成功、清理和交付成功、墙钟/活跃/排队时间及人工介入。关键安全门禁要求零违规。性能目标来自实测试运行，不编造延迟或准确率。

## 12. 交付计划与决策

| 增量 | 交付物 | 推进前门禁 |
|---|---|---|
| 1. 验收现有路径 | 完成候选样例/限定 setup 工作；保持现有发布和 provider 边界 | G1-G3；如实处理失败/报告/清理 |
| 2. 共享 discovery 契约 | Feature 计划/观测/报告 schema、能力注册表扩展、浏览器模块 | G0-G2；不强制计划/仅源码模式使用 MCP |
| 3. 持久组合 | Feature 日志、子操作、真实回调/watcher 准入、限定取消与重建 | G6，包括独立任务取消测试 |
| 4. AT 与真实 feature | 已验收 discovery capture 适配器、独立评价、多路径报告 | 每个声明支持的 profile 都满足 G4-G5 |
| 5. 发布/切换 | 可安装有界工作流、兼容矩阵、操作指南和回滚 | G7；只推广新运行，当前运行保持固定 |

不要在演练当前样例前重写整个系统。先实现具备真实输出的一个纵向切片，再扩展支持能力。交付有限且已验收的 profile，不把每个可选 AT 都标为支持。

初始决策：保持现有 manifest；复用当前运行时和归属权威；内置可复用模块，而不是要求安装全部兄弟包；不增加工作流引擎或托管 Agent 平台；报告保持私有；修复/发布不属于 discovery。Agent 数量是优化问题，不是正确性要求；子代理不可用不阻塞基础设计。

先有静态支持 profile 和显式能力元数据，再在已验收能力之间进行有界任务驱动选择。不能为图数据库、新 Harness 或 skill 优化器延误现有样例。离线演进是之后选择加入的增量，不是增量 1-5 的前提。

实现前，通过宿主探测和适配器一致性确认：实际 Copilot/MCP 兼容性、已验收通用浏览器连接器、原资源权威中的类型化 feature 执行支持，以及首批真实 AT profile。未知仍标为不支持。这些决策改变时，在同一经过评审的变更中更新本文及接受用例；只发布设计不安装任何能力，也不完成验收。

## 13. 证据驱动维护与离线演进

逻辑上分开原始轨迹/证据、整理后的过程知识和权威执行状态。召回的恢复建议可以提出假设，但是否可执行仍由实时归属/健康检查决定。私有源码、产品数据和媒体保留在批准的存储/可见性边界中；本设计不授权上传托管记忆服务。

起初保留显式能力目录和声明组合。真实运行暴露选择失败后，在相同 feature 环境、预算和必需行下，将有界检索/排序候选与静态基线比较。记录每项能力被选择、排除或不可用的原因。

检索边/描述与 skill 过程分开优化。保留失败特征、候选编辑、被拒尝试和复发回归。限制编辑范围；冻结评判标准、所需证据和授权门禁。通过经过评审的变更应用问题历史和编辑预算；优化器不得修改检查器。

推广前，使用独立正常/缺陷回归用例和留出 feature 场景，而不只是促成变更的样例。方差需要时重复配对运行。记录效果量、不确定性、累计 token、上下文峰值、延迟和基础设施失败。已知 16 行样例仍是回归门禁，不是对所有 feature 泛化的证据。

自适应组合的额外接受用例：

| 情况 | 必需结果 |
|---|---|
| 必需 AT skill 排名落在检索截断之外 | 保留必需行；包含其已验收 provider，或显式报告缺口 |
| 学习关系与归属/证据策略冲突 | 拒绝提议的执行，不削弱硬约束 |
| 运行中出现新 skill/provider 版本 | 已提交操作保持固定，不以替换版本重放 |
| Skill 修改通过削弱预期提高分数 | 拒绝候选；受保护标准与已知缺陷检测保持不变 |
| 候选在训练用例成功、在留出用例回归 | 保留基线或报告证据不足，不自动推广 |
| 记忆召回在当前忙碌宿主上的成功恢复 | 尊重当前归属；历史成功不授予访问权 |

在固定预算下衡量受支持且有结论的覆盖、已知漏报和抽样误报，而非原始 bug 数。即使产品准确性单列，也把基础设施错误计入端到端可靠性。要求无重复外部作用、无归属违规。保留恢复、清理与交付义务；自适应不能重新制造任务取消耦合。

只有获得独立证据支持的候选，才能通过经过评审的版本、已验收 profile 和回滚机制推广到新运行。证据不足保留最后接受的基线。限制改进轮次，回归时停止；更多执行历史不保证组合质量单调提升。
